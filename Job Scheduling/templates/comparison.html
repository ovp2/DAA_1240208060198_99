Complexity Analysis & Asymptotic Formulations

Exact theoretical bounds derived from code inspection of the actual implementations:

Algorithm Paradigm Time Complexity Space Complexity Algorithmic Mechanism
Greedy Algorithm Greedy Heuristic O(N log N + N × M) O(N + M) Timsort ordering O(N log N) followed by single-pass allocation O(N × M). Requires linear memory for job records and resource states.
Dynamic Programming Exact Optimization O(N log N + N × T + N × M) O(N × T) EDF deadline ordering followed by 2D tabular construction of size (N+1) × (T+1). Backtracking takes O(N + T). Requires quadratic/pseudo-polynomial matrix memory.
Theoretical Complexity vs. Measured Execution Time: Important DAA Distinction: Asymptotic notation (Big-O) describes the growth rate of algorithm resource requirements as input sizes approach infinity. Measured execution time reflects concrete clock wall-time on a specific hardware CPU, operating system, and memory architecture. While empirical runtimes demonstrate polynomial vs pseudo-polynomial trends, real clock times are influenced by constant factors, CPU caching, Python interpreter overhead, and memory bandwidth. Empirical testing corroborates theoretical predictions but does not mathematically prove them.
Definitions: N = Number of candidate jobs | M = Number of available resources | T = Bounded scheduling timeline capacity window.
⚡

GREEDY ALGORITHM

Locally Optimal Decisions: Selects the immediate best candidate at each step according to the multi-criteria priority sort (profit > deadline > priority > burst) without reconsidering earlier choices.
Constraint Checking: For each candidate, verifies deadline compatibility and available resource capacity. If feasible, assigns the resource immediately.
Memory Footprint: Only requires linear space O(N + M) since it does not build or maintain an intermediate state matrix.
Trade-off: Highly efficient and scales easily to thousands of jobs, but can produce suboptimal total profit when combination effects favor multiple smaller jobs over a single large one.
🧠

DYNAMIC PROGRAMMING

Overlapping Subproblems: Formulates the decision state DP[i][t] as the optimal subset achievable using the first i jobs within available scheduling timeline capacity t.
Intermediate Table Storage: Solves subproblems once and caches solutions in a 2D matrix, evaluating include vs. exclude transitions at every cell.
Backtracking Reconstruction: Reconstructs the exact selected job subset by traversing backwards through the filled matrix.
Trade-off: Guarantees optimal global profit for bounded timeline capacity, but memory and execution time scale with O(N × T), making large capacities impractical.

How to Demonstrate (Viva & Presentation Walkthrough)

Step-by-step presentation roadmap for demonstrating the system during your Design & Analysis of Algorithms project review:

1. Add Jobs: Open Jobs to show job attributes (burst, deadline, profit, priority, required resource).
2. Add Resources: Open Resources to demonstrate multi-type hardware and worker capacity limits.
3. Run Greedy: Click "Run Greedy Algorithm" on Schedule to show greedy dispatch.
4. View Schedule: Inspect the resulting timeline, assigned resources, and missed jobs reasons.
5. Reset Schedule: Click "Reset Schedule" to restore all jobs to Pending without deleting data.
6. Run DP: Click "Run Dynamic Programming" to execute the 0/1 deadline-constrained DP engine.
7. View DP Table: Expand "View DP Table" to show the live matrix DP[i][t] and backtracking steps.
8. Open Comparison: Navigate to this Algorithm Comparison tab.
9. Select Dataset: Choose Small (10) or Medium (50) to demonstrate identical input benchmarking.
10. Run Comparison: Click "Run Comparison" to trigger live execution across 5 repeated trials.
11. Explain Runtime: Contrast the measured microsecond runtimes between Greedy and DP.
12. Explain Complexity: Reference the theoretical O(N log N) vs O(N × T) complexity table.
13. Explain Trade-offs: Conclude by discussing speed vs optimality trade-offs: Greedy is faster and lightweight; DP achieves exact optimal profit when state space permits.
