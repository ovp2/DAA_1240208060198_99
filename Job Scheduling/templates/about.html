1. Problem Statement

Given a set of $n$ candidate jobs $\mathcal{J} = \{J_1, J_2, \dots, J_n\}$ where each job $J_i$ requires processing duration $p_i$, has arrival time $a_i$, completion deadline $d_i$, priority rank $\pi_i$, and yields monetary reward / profit $v_i$.

The objective is to allocate non-overlapping execution intervals on $m$ heterogeneous resources $\mathcal{R} = \{R_1, \dots, R_m\}$ with finite operating capacities $H_k$ to maximize cumulative profit $\sum_{J_i \in \mathcal{S}} v_i$ subject to completion deadlines $C_i \le d_i$ and machine resource compatibilities without collision.

3. Algorithms Used & Mathematical Formulations

Detailed breakdown of the two central algorithmic paradigms implemented in the scheduling engine:

Greedy Approach O(n log n + n·m)

Priority & Density Heuristic

The Greedy algorithm evaluates jobs based on a multi-tier heuristic ranking:

Key(J_i) = (d_i ↑, -(v_i / p_i) ↓, π_i ↑)
  • • Step 1: Sort candidate jobs by deadline ascending, profit-to-burst density descending, and priority rank.
  • • Step 2: Sequentially inspect each job against available compatible resources.
  • • Step 3: Schedule job on the earliest available machine if completion $C_i \le d_i$.
  • • Step 4: Irrevocably commit decisions in single pass without backtracking.
  • • Memory: $\mathcal{O}(n + m)$ linear working space.
Dynamic Programming O(n log n + n·T + n·m)

Optimal Substructure & Recurrence

Dynamic Programming decomposes the deadline-constrained problem into overlapping subproblems over states $(i, t)$:

DP[i][t] = max(DP[i-1][t], DP[i-1][t - p_i] + v_i)
∀ t ∈ [p_i, min(T, d_i)]
  • • Step 1: Sort jobs by deadlines to ensure chronological compatibility.
  • • Step 2: Compute 2D state matrix $\text{DP}[0 \dots n][0 \dots T]$ storing optimal profit values.
  • • Step 3: Backtrack through table from $(n, T^*)$ to reconstruct the exact subset of selected jobs.
  • • Step 4: Assign reconstructed jobs to feasible resources preserving non-overlapping windows.
  • • Memory: $\mathcal{O}(n \cdot T)$ 2D state table (bounded by capacity limit).

Delete protection blocks removal of resources currently allocated in active schedules.

5. Complexity Analysis: Theoretical vs. Measured Time

Careful differentiation between formal asymptotic Big-O bounds and physical wall-clock performance:

Algorithm Time Complexity Space Complexity Practical Scalability Limit
Greedy Algorithm Ο(n log n + n × m) Ο(n + m) High (≥ 100,000 jobs)
Dynamic Programming Ο(n log n + n × T) Ο(n × T) Capacity Bounded (N ≤ 200)
Critical DAA Distinction: Theoretical complexity characterizes asymptotic growth as $n \to \infty$. Measured wall-clock time includes implementation constant factors, memory cache locality, CPU branch prediction, and Python runtime overhead. Empirical testing validates practical trade-offs but does not replace mathematical proof.

6. Performance Testing Methodology

Empirical benchmarking utilizes Python's nanosecond-resolution time.perf_counter(), isolating algorithmic execution from database queries, template rendering, and browser networking.

  • ✓ Identical Datasets: Seeded deterministic generator produces identical deep-copied inputs.
  • ✓ Multi-Run Trials: 5 repeat executions compute Average, Minimum, and Maximum timing.
  • ✓ DP Capacity Guard: Safely prevents memory exhaustion when $N \ge 500$ or state space exceeds $300,000$.
  • ✓ Data Isolation: Benchmark runs in-memory and never modifies active database schedules.
